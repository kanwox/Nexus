## 修复方案：Nexus (Mihomo Android) 审计整改

### 前置决定（已确认）
- 范围：**全部修复**（安全 + 稳定 + 性能 + i18n + 构建/CI/测试）
- 签名：**生成全新 keystore**，不提交，口令外部注入
- 明文：**base 全局禁止，仅放行 127.0.0.1/localhost**
- 额外交付：先在 `main` 上开分支 `fix/audit-remediation` 再改，不自动提交

---

### 阶段 1 — 安全加固（P0）

1. **签名密钥外部化**（`app/build.gradle.kts:24-46`）
   - 删除 `signingConfigs.unified` 的硬编码口令；改为从 `local.properties`/环境变量读取 `RELEASE_STORE_FILE`、`RELEASE_STORE_PASSWORD`、`RELEASE_KEY_ALIAS`、`RELEASE_KEY_PASSWORD`，缺省时 release 不套用签名配置并打印警告。
   - `debug` 移除自定义签名，改用 Android 自动调试签名。
   - 用 `keytool` 生成新 keystore 到仓库外（如 `%USERPROFILE%\.android\nexus-release.jks`），本地写进已被忽略的 `local.properties`；CI 用 GitHub Secrets。
   - `git rm --cached app/nexus.keystore`，删除工作区文件。
   - `.gitignore` 增加 `*.jks`、`*.keystore`、`keystore.properties`、`signing.properties`。

2. **禁止全局明文**（`res/xml/network_security_config.xml:7`）
   - `<base-config cleartextTrafficPermitted="false"/>`，保留 localhost `domain-config`。
   - 在 `ConfigManager.downloadSubscription`/`updateSubscription`（L147/L189）与 `ScriptManager` 下载处预校验 URL scheme，http:// 返回明确中文错误而非 OkHttp 的 `UnknownServiceException`。

3. **Rhino 沙箱加固**（`ConfigScriptEngine.kt:188-241`）
   - `initStandardObjects()` → `initSafeStandardObjects()`，并 `setClassShutter { false }`（1.7.15 已确认具备该 API）。
   - 增加指令数超时：自定义 `ContextFactory` 覆写 `observeInstructionCount`，超阈值抛异常，防止脚本死循环拖死配置加载。

4. **配置净化结构化**（`ConfigManager.kt:375-397`）
   - 改为 SnakeYAML 解析为 Map 后删除受保护顶层键，再 dump。彻底消除引号/重复键绕过。
   - 保护键扩充：`external-ui`、`external-ui-url`、`interface-name`、`routing-mark` 等。
   - 解析失败时回退到加固版文本过滤（key 去引号），并记日志。

5. **移除未使用的 REST 控制器**（零攻击面，替代加 secret）
   - 从生成 header 删除 `external-controller: 127.0.0.1:9090` 与 `secret: ""`（`ConfigManager.kt:410-411`）。
   - 删除 `ClashCore.startHttp/stopHttp` 调用（`ClashCore.kt:79,104`；`MihomoVpnService.kt:209,265`）；函数体保留或一并删除。

6. **备份收紧**（`AndroidManifest.xml:16`）：`allowBackup="false"`。
7. **发布包不再随附密钥**：删除根目录 `Mihomo.apk`（未跟踪的陈旧产物）。

### 阶段 2 — 稳定性与并发

8. **VPN 启停状态机**（`MihomoVpnService.kt`）
   - 新增 `startJob: Job?`；`startVpn()` 内 `startJob?.cancel()` 后赋值，用 `Mutex`/`AtomicReference` 串行化 start/stop。
   - `stopVpn()`（L258）先取消 `startJob` 再清理。
   - `onDestroy()`（L335）取消 `serviceScope`、`stopTun`/`stopHttp`、关闭 `vpnInterface`、`stopForeground`、复位 `_vpnState`（幂等）。
   - `stop()`（L70）的 `startService` 包 `runCatching`，避免后台启动受限抛异常。

9. **内核初始化与加载**（`MihomoApplication.kt:22`、`ClashCore.kt:55-107`）
   - `init` 改异步：Application 里投到 IO scope；`initialized` 标 `@Volatile`；新增 `suspend fun ensureInitialized()`，供 VpnService/`ensureCoreLoaded` 等待。
   - `load()` 的 `deferred.await()` 包 `withTimeout(20s)`，超时返回失败而非永久 STARTING。
   - `SettingsScreen.kt:283` 的 `getCoreVersion()` 移出组合期（`remember` 或异步 State）。

10. **自动测速竞态**（`MainActivity.kt:466-518`）
    - `isAutoTestingInProgress` → `AtomicBoolean`，在主线程同步 `compareAndSet` 置位。
    - 持有单个 `autoTestJob`，触发前取消旧任务；把测速主体抽成 `suspend fun`，auto 路径直接 await，杜绝 `finally` 提前清标志与并发重叠。
    - `lastAutoTestTimes` 提升到稳定持有者，避免重组/旋转丢冷却。

11. **App Routing 加载**（`MainActivity.kt:552-564`）：去掉嵌套 `lifecycleScope.launch`，在 `LaunchedEffect` 内直接 `withContext(Dispatchers.IO)`，离开页面自动取消。

12. **脚本变更后失效解析缓存**：在 `ScriptManager.saveScripts`/`saveRewrites`（L58/L204）调用 `ProfileParser.clearCache()`。

13. **OkHttp 连接泄漏**：5 处 `execute()` 改 `response.use { }` —— `ConfigManager.kt:158,201`、`ScriptManager.kt:76,158`、`RemoteIcon.kt:72`；顺带三处 client 统一（可选）。

14. **其它**：删除 `Bridge.kt:30-35` 泄露 fd 的死代码块；`System.currentTimeMillis()` ID 改 `UUID`（`ConfigManager.kt:168` 等）；`Theme.kt:102` 的 `(context as Activity)` 改为安全查找。

### 阶段 3 — 性能与状态

15. **组合期同步 IO/解码移出主线程**
    - `SettingsScreen.kt:75`、`ScriptsScreen.kt:41`、`ProfileOverrideScreen.kt:36`（`ScriptManager.getScripts`）、`MainActivity.kt:123`（`getProfiles`）→ `produceState`/`LaunchedEffect + Dispatchers.IO`。
    - `ProfilesScreen.kt:781` 的 `readText()` → 打开编辑弹窗时异步加载。
    - `RemoteIcon.kt:97-100` → 只查内存缓存，磁盘/解码交给已有 `LaunchedEffect`（新增 `getMemory()`）。
    - `AppRoutingScreen.kt:289-303` → `produceState` 在 Default 线程绘制图标。
    - `ClashCore.reset()`（`SettingsScreen.kt:301`）加确认弹窗并后台执行。

16. **旋转保持状态**：`MainActivity.kt` 的 `currentTab`、`currentSubScreen`（enum name Saver）、`overrideTargetProfile`（存 id）、`selectedProfileId` 及弹窗标志改 `rememberSaveable`。

17. **死开关生效**（`SettingsScreen.kt:72-73`）
    - `SettingsManager` 新增 `allowLan`、`fakeIpEnabled` 持久化属性。
    - 仿 `bootOnStartup` 模式提升到 MainActivity 写入；`allowLan` 写入生成 header 的 `allow-lan:`（恢复真正的局域网共享），`fakeIpEnabled` 控制 header 的 `enhanced-mode` 与 `fake-ip-range`。

### 风险与验证
- **启用 minify 风险最高**：需 `assembleRelease` 成功并在真机冒烟（连接、测速、订阅、脚本）。若你希望更稳，可把 20 拆成独立第二步，先只补 keep 规则。
- **新密钥**：已安装用户无法覆盖升级，需卸载重装。
- **禁止明文**：http:// 订阅将不可用，必须换 https。
- **i18n**：ru 文案由我生成，需你抽查。
- **验证手段**：每阶段结束跑 `gradlew compileDebugKotlin detekt test`；阶段 1/2 完成后 `assembleDebug` 真机回归 VPN 启停/订阅/脚本；全部完成后 `assembleRelease` 冒烟。
